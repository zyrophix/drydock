# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| Latest GitHub release | yes |
| Older releases | no — upgrade |

## Reporting a vulnerability

**Do not open a public issue for security vulnerabilities.**

Use GitHub's private vulnerability reporting (*Security → Report a vulnerability*) on the repo, or contact the maintainer directly.

Include: affected version, platform, impact, and reproduction steps. Expect an initial response within 7 days. Coordinated disclosure: fixes ship before details go public.

## Scope

In scope: anything that breaks the project's stated safety promises. Out of scope: the tool's intended behavior when used as documented, and issues in third-party dependencies (report upstream).
